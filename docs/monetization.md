# ZyDrive 开源与收费设计

> 状态：设计稿（2026-11-25）。协议组合（核心 MPL-2.0 + 界面 MIT）已于 2026-11-25 由用户确认并落地（根 `LICENSE`、`frontend/LICENSE`、各源文件头 SPDX 标识均已加）。
> 收费暂缓（2026-11-25）：先按第 5 节的权益清单画免费 / Pro 分界线，再定价。
> 落地时机：v0.8.5 推完之后，避免与正在跑的修复轮冲突。

## 1. 目标

- 开源拿用户与口碑，收费靠 Pro 功能，二者不互相打架。Agent 定时跑是 Pro 功能，用户自己部署到自己的服务器，我们不提供托管服务器、不做账号订阅。
- 参考模型：收费模式学 Air Explorer（免费版 + Pro 激活码）；开源结构学 Alist（核心开源、单独的收费件）；引擎开源学 rclone（但不用它的全开源 + 卖支持合同）。

## 2. 仓库与协议

| 仓库 | 公开/私有 | 内容 | 协议 |
|---|---|---|---|
| `luckzk/zy-drive` | 公开 | 后端 Go（驱动、同步、传输引擎）+ `frontend/`（界面）+ 文档 | 根 `LICENSE` 是 MPL-2.0，`frontend/LICENSE` 是 MIT |
| `luckzk/zy-drive-pro` | 私有 | Pro 功能模块 + License 激活验证 | 专有 |
| Agent 定时调度（自部署） | 私有（Pro 功能） | 调度器 + License 校验；用户自己部署到自己的服务器，不提供托管服务 | 专有 |

- **不拆 UI 仓库**：一个人开发，UI 与后端每次一起改（加个 Bind 就要前后端同版本对上）；桌面应用一次打包，单仓库一个命令搞定。协议边界用 `frontend/LICENSE` + 文件头 SPDX 标识解决，不靠仓库边界。
- 什么时候再考虑拆：有第二个人长期只改 UI，或者要出独立网页版（不打包进桌面应用）时。

## 3. 开源范围（公开仓库）

- 六个驱动：S3/R2、Dropbox、Google Drive、OneDrive、Drime、本地文件夹
- 同步引擎（比较 / 计划 / 预览 / 执行）、传输引擎
- 桌面 UI（React + Tailwind）、授权流程、CLI、Agent 客户端
- 文档、注册指南（`docs/oauth-apps/`）

## 4. 闭源范围（私有仓库）

- `zy-drive-pro`：Pro 功能模块、License 激活验证
- Agent 定时调度（自部署）：调度器 + License 校验；用户自己部署到自己的服务器，不提供托管服务、不做账号订阅系统
- 原则：Pro 功能不能只是公开仓库里的一个开关（那样从源码编译一下就绕过了）。Pro 代码放私有模块，核心通过接口调用它。

## 6. 免费 / Pro 功能表（草案，待按权益清单定）

| 功能 | 免费版 | Pro（$21/年 或 $42 终身，按设备激活码） |
|---|---|---|
| 每云账号数 | 1 个 | 不限 |
| 浏览 / 上传 / 下载 / 单向复制 | 有 | 有 |
| 同步 | 只读同步（单向复制，不删文件） | Mirror、双向、定时调度 |
| 并发 | 2 路 | 按设置来，限速也放开 |
| 批量传输 / 断点续传 / 冲突可视化 | 无 | 有 |
| Agent 定时跑（自部署） | 无 | 有，包含在 Pro 里，不另收费；用户自己部署到自己的服务器 |

- 激活方式：桌面 Pro 与 Agent 定时跑都用离线激活码（买完邮件发码，输进去解锁，不用注册账号、不登录我们的服务器）；Agent 部署到用户自己的服务器（Docker / systemd），凭证由用户自己导出加密配置包、拷到服务器上导入，不经过我们的服务器。
- 收款：海外用 Paddle 或 Lemon Squeezy（代处理各国增值税）；国内早期用爱发电验证需求，微信/支付宝要国内主体。

## 7. 协议选择（拟采用）

| 协议 | 用在哪 | 理由 |
|---|---|---|
| MPL-2.0 | 核心（后端 Go） | 文件级 copyleft：引擎的改进必须回馈开源，同时 Pro 模块作为独立文件可以闭源，互不污染。open-core 的标准选择 |
| MIT | 界面（`frontend/`） | 门槛最低，社区最愿意改 UI、提 PR；与 Alist 的 alist-web 一致 |
| 专有 | Pro 模块、Agent 服务端 | 不开源 |

- 不用 AGPL-3.0：Agent 定时调度是作为 Pro 出售的自部署服务端功能，AGPL 会逼着把这部分服务端代码也开源，跟收费模式打架；而且接受外部贡献后改协议要所有人同意。
- 不用全 MIT：零保护，别人能原样拿走改个名就卖。
- 接受外部贡献前：贡献指南里写明，提交 PR 即同意代码按对应协议开源；否则以后改协议要一个个找人。是否签 CLA 以后再定。

## 8. 落地步骤

1. 仓库根目录加 `LICENSE`（MPL-2.0 全文）。
2. `frontend/` 下加 `LICENSE`（MIT 全文）。
3. README 加 License 说明：哪部分是什么协议、闭源部分是哪些、去哪买 Pro。
4. 每个源文件头加一行 `SPDX-License-Identifier: MPL-2.0` 或 `MIT`。
5. 新建私有仓库 `luckzk/zy-drive-pro`（Pro 模块 + 激活验证），核心留出接口，不先写功能。
6. 贡献指南加 PR 协议条款（见第 7 节）。

## 9. 风险与注意

- 内置共享 OAuth Client ID：目前在公开仓库里（公开标识，本来就可以公开）。开源后别人 fork 也会带着同一套 ID 用，共享客户端被滥用的风险会变大；Pro 阶段给付费用户单独的客户端或自己的注册流程。
- Fork 风险：MPL-2.0 下别人可以 fork 引擎，但改了引擎要开源回来；UI 是 MIT，别人能拿去改——接受这一点，护城河是 Pro 功能 + 持续更新与支持，不是代码本身。
- 不提供托管服务器：就没有服务器成本、运维与数据责任；但 Agent 凭证怎么安全交到用户自己的服务器上，是 v0.9.0 调度器接线时要设计好的（桌面导出加密配置包、服务器上导入，不经过任何中间服务器）。
- 时间点：现在不用急着收。先让产品跑起来、让人用上，v0.9.0 的 Agent 调度器和批量传输就是付费功能的底座；等有人每天在用、开始问“能不能多加点任务”时再上付费墙。
